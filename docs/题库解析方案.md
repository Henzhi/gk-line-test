# 题库解析方案（PDF → 结构化数据 → 入库）

> 核心痛点：手里只有行测 PDF 卷子 + 单独的答案，没有结构化题库。
> 本文档定义如何把 PDF 变成可入库的题目数据。

## 一、行测题型特征与难点

| 模块 | 子模块 | 是否依赖图片 |
|---|---|---|
| 常识判断 | 政治/法律/历史/科技… | 基本不依赖 |
| 言语理解 | 逻辑填空/片段阅读/语句表达 | 基本不依赖 |
| 数量关系 | 数学运算/数字推理 | 部分依赖（图表） |
| 判断推理 | 图形推理/定义判断/类比推理/逻辑判断 | **图形推理强依赖图片** |
| 资料分析 | 统计图表/文字材料 | **强依赖表格图表** |

**结论**：纯文本提取（PDFBox/POI/Tesseract）会丢失图形推理题和资料分析的图表信息，不可行。
必须走**多模态大模型**解析（把 PDF 页面渲染成图片喂给模型）。

## 二、目标数据结构（JSON）

每道题一个 JSON 对象，与 `question` 表字段一一对应：

```json
{
  "module": "判断推理",
  "subModule": "图形推理",
  "stem": "从所给的四个选项中，选择最合适的一个填入问号处……",
  "optionA": "选项A内容",
  "optionB": "选项B内容",
  "optionC": "选项C内容",
  "optionD": "选项D内容",
  "answer": "B",
  "analysis": "解析文字（若原卷无解析可留空）",
  "images": ["https://xxx/img1.png"],
  "difficulty": 3,
  "source": "2023年国考·行测·副省级"
}
```

批量文件格式：`data/json/<卷子名>.json`，内容为数组 `[ {...}, {...} ]`。

## 三、解析流程

```
PDF 原卷 ──①──> 按页渲染成图片 ──②──> 多模态大模型识别 ──③──> 结构化 JSON ──④──> 人工校对 ──⑤──> 导入 MySQL
```

1. **① 渲染**：用 PDF 转图工具（PyMuPDF/pdf2image）把 PDF 每页转 PNG，分辨率 150-200 DPI。
2. **② 识别**：把每页图片（含题干+选项）+ 该卷的答案页喂给多模态模型，用 Prompt 约束输出 JSON。
   - 推荐模型：豆包(Doubao)、通义千问-VL、GLM-4V、DeepSeek-VL 等（国内模型对中文行测识别更好）。
   - **图片处理**：图形推理、资料分析的图不能丢，需把题干中的图单独截出存成图片 URL，JSON 里记 `images`。
3. **③ 输出校验**：程序校验 JSON 合法性、`answer` 是否为 A/B/C/D、模块是否在枚举内。
4. **④ 校对**：做一个轻量校对界面（或直接人工翻 JSON），重点核对：图形题图片是否完整、答案是否正确、选项是否对位。
5. **⑤ 入库**：写导入脚本/接口，批量 INSERT 到 `question` 表；整套卷子同时写 `paper` + `paper_question`。

## 四、模块/子模块枚举（统一口径）

```
module 取值: 常识判断 | 言语理解 | 数量关系 | 判断推理 | 资料分析

subModule 取值:
  常识判断: 政治 | 法律 | 经济 | 历史 | 科技 | 地理 | 文化 | 其他
  言语理解: 逻辑填空 | 片段阅读 | 语句表达
  数量关系: 数学运算 | 数字推理
  判断推理: 图形推理 | 定义判断 | 类比推理 | 逻辑判断
  资料分析: 统计表 | 统计图 | 文字资料 | 综合资料
```

## 五、答案匹配策略

原卷答案通常是单独一页/一份 PDF，按题号列出（如 `1-5: ACBDA`）。两种处理方式：

- **方案A（推荐）**：解析题干时，把答案页图片一并传给大模型，让模型直接输出每题 `answer` 字段，一步到位。
- **方案B**：单独解析答案页 → 得到「题号→答案」映射表 → 程序按题号合并到题目 JSON。

## 六、导入工具选型

- 解析脚本建议用 **Python**（PyMuPDF + requests 调大模型 API），产出 JSON 放 `data/json/`。
- 入库用 Java 后端写一个「题目批量导入」接口，或先用 SQL/脚本直插数据库。

## 七、后续要确认的问题

1. 大模型 API 用哪家（豆包/通义/GLM…），是否已有 API Key？
2. PDF 有多少套、每套多少题？决定批量解析的成本和耗时。
3. 原卷答案是否带「解析」？不带的话解析字段先留空，后续可让大模型补充。
4. 图形题图片存储用本地文件还是对象存储（OSS）？
